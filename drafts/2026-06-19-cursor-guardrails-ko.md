Cursor가 $60B 규모로 성장하는 궤적을 그리고 있다. Anthropic 데이터는 냉혹하다. 개발자 60%가 매일 AI를 사용하지만 실제 위임 비율은 0~20%에 불과하다. 위임의 간극은 모델을 키운다고 해결되지 않는다. 오케스트레이션 계층과 철저한 가드레일이 핵심이다. 안드로이드 폰 하나로 11대 VPS를 운영하는 우리의 경험이 이를 증명한다.
---
DN42 파산 사건은 강력한 경종이었다. 네트워크 스캔과 API 키만 받은 에이전트가 안전장치 없이 비용을 폭발시켜 운영자를 파산시켰다. 악의가 아니라 가드레일 부재가 원인이었다. AI 실패의 78%는 사용자에게 보이지 않는다. 잘못된 출력을 아무런 의심 없이 받아들인다. 컨텍스트 부패는 긴 세션을 파괴한다. 토큰 증가만으로는 해결되지 않는다.
---
에이전트와의 실제 대화 중 90%는 불과 1~2턴 만에 끝나버린다. 세션이 길어질수록 성공률은 45%에서 8% 미만으로 급격히 폭락한다. 이 문제를 해결하는 실질적인 방법은 제한된 자율성(bounded autonomy)이다. 에이전트는 변경안을 작성하고 PR 초안을 제안할 수는 있지만, 사람이 GitHub에서 직접 검토하고 머지 버튼을 누르기 전까지는 절대로 프로덕션 환경에 반영될 수 없다. 이 단순하면서도 강력한 단 하나의 규칙이 우리의 위임 간극을 완전히 메워주었다.

우리 시스템의 핵심인 공융(gongyung) Termux 안드로이드 노드가 Hermes 에이전트 전체 플릿을 효과적으로 조율하고 있다. X 포스팅 크론 작업(5-tweet 고정 템플릿과 한 줄 문자 수 검증 로직 적용), MCP 연결 실패시 즉시 로컬 위키 캐시로 폴백하는 메커니즘, 첫 번째 트윗에 붙일 15초 비디오 슬라이드 자동 생성까지 모두 처리한다. 특히 모든 프로덕션 수준 변경은 반드시 사람의 코드 리뷰와 PR 머지를 거쳐야만 실제로 적용된다.
